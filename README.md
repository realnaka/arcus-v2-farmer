## 1. 这是干什么的

| 问题 | 答案 |
|---|---|
| 目标 | 在永续 DEX 的积分季里，用**有限本金**换到尽量多的分与排名 |
| 手段 | 持有一条**美元中性的多腿价差**，把名义尽量大、时间尽量长地挂在场上 |
| 裁判 | ① 每个窗口的 **OI-time**（名义·小时）② 是否被 ADL/强平 ③ 摩擦成本（手续费 + 资金费） |
| 不做 | 不追成交量、不刷轮次、不做高频撤挂循环 |

**30 秒结论**

- 积分的**主项是 OI-time**（持仓名义对时间的积分）；成交量只是次项，而且**快速换手会被折扣**。
- 一份保证金能撑起约 `2 × 每边倍数` 的**总名义**；美元中性让多空两条腿**都计 OI**，
  所以同样的钱，拿到的 OI 是单边仓的两倍。
- 剩下的全是工程问题：**怎么不被强平**、**怎么不被 ADL 挑中**、**怎么让挂单不产生无意义摩擦**。

## 2. 核心逻辑：积分奖励的是「持仓时间」，不是成交量

积分季按周发放一个**固定分数池**，榜上是**排名分配**，不是绝对计价。
把公开样本与官方周报的汇总量放在一起，一阶关系是：

```
积分  ≈  OI-time × 效率
OI-time = Σ(持仓名义 × 持仓小时)
效率   ≈ 每 $1M 名义持有一周 = 1,000–4,000 分（加密币对偏低，RWA/股票永续偏高）
```

三条能直接改变做法的推论：

| 推论 | 证据方向 | 对策略的含义 |
|---|---|---|
| **持仓本身计分，不需要交易** | 有「本周 0 交易、只保持原有仓位」仍然拿分的样本 | 目标是不动，不是动得快 |
| **成交量既不充分也不线性** | 成交量放大 10 倍，分数只放大 ~4.5 倍；多个大成交量账号接近 0 分 | 刷量本身不是解法 |
| **快开快平被折价** | 「剥头皮」类样本残差中位数约 **0.2×**（打两折） | 高频网格对积分是**负贡献** |

还有一层**免费乘数**：官方把「常规时段」定义为 **04:00–20:00 ET**，
其余时间（20:00–04:00 ET、周末、假期）属于 RWA / 隔夜加成窗口。同一份 OI，
放在加成窗口里效率更高。**一个 24/7 持有的仓位自动拿到约 52% 的加成占比** ——
这正是「持有」相对「只在盘中交易」的优势。

推导过程、样本口径修正与上下界见 [docs/points-model.md](docs/points-model.md)。

## 3. V2 策略结构：记忆体篮子价差

标的是一个**记忆体主题 ETF** 和它的成分股在 Arcus 上的永续。
该 ETF 里只有约 54% 的权重能在 Arcus 上交易，余下（三星、CXMT、希捷、西部数据、
铠侠、南亚、华邦）没有对应永续 —— **这部分买不到**。

于是 V2 做的是：**做多能买到的那部分（按 ETF 内权重归一），做空等额的 ETF 本身**。

```
        多腿（按可交易权重归一）                空腿
  ┌────────────────────────────────┐   ┌──────────────────┐
  │ MU-USD   27.36% / 0.5414       │   │                  │
  │ SKHY-USD 22.13% / 0.5414       │   │   DRAM-USD       │
  │ SNDK-USD  4.65% / 0.5414       │   │   (ETF 本身)      │
  └────────────────────────────────┘   └──────────────────┘
              └────────── 等名义 ──────────┘
                            ↓
        净敞口 ≈ 空掉那 45.86% 买不到的成分
```

| 项 | 取值 | 说明 |
|---|---|---|
| 多腿 | MU / SKHY / SNDK | 按 ETF 内权重归一 ⇒ 0.5054 / 0.4088 / 0.0859 |
| 空腿 | DRAM | 与多腿合计等名义 ⇒ 美元中性 |
| 每边名义 | `权益 × 每边倍数`（默认 3.0×） | 总名义 = 6.0× 权益 |
| 净方向 | 接近 0（残差就是那 45.86% 的非交易成分） | 目的是拿 OI，不是赌方向 |

**为什么是这个形状**，而不是更简单的单腿做多：

1. **美元中性 = 一份保证金买到两份 OI**。多 $1 + 空 $1 = $2 的 OI，保证金只押一份。
2. **风险从「方向」换成「基差 + 保证金管理」**。多腿与空腿高度相关，同涨同跌的部分被抵消，
   剩下的是两者之间的价差波动。
3. **资金费方向可选**：RWA 永续多头长期付费，做空溢价的一边能把资金费从成本变成收入。

代价同样明确：**ETF 与成分股之间会有溢价/折价漂移**，且 ETF 权重会随季度再平衡变化，
必须定期重算（见 [第 8 节](#8-风险与边界必读)）。

## 4. 运行机制：排班、止损、ADL 复位

策略参数全部在 [`arcus-farmer/config/spread-v2.yaml`](arcus-farmer/config/spread-v2.yaml)；
调度器是 [`arcus-farmer/tools/spread_schedule.py`](arcus-farmer/tools/spread_schedule.py)。

### 4.1 仓位：默认冻结，不追价格

| 状态 | 行为 |
|---|---|
| **冻结（默认 `hold_rebalance: true`）** | 仓位开好就不动。不跟权益漂移、不跟价格漂移、不做窗口切仓 |
| 仍然活着 | 止损阶梯（只降不升）与 ADL 复位 |

为什么默认冻结：**第一版调度器每 15 秒做一次盯市，2.5 小时里下了 124 单**，
全部来自「权益抖了几美元」这类噪声。对积分是负贡献，对手续费是纯支出。
冻结之后，唯一会产生订单的事情是**真的触发了风险规则**。

### 4.2 杠杆与东部时间排班

Arcus 的「常规时段」是 04:00–20:00 ET（含美股盘前盘后），初始保证金 10%；
加成窗口是 20:00–04:00 ET + 周末，初始保证金 15%。

| ET 时段 | 归类 | 每边名义 |
|---|---|---|
| 04:00–20:00 | 常规 | `base_per_side`（默认 3.0×） |
| 20:00–21:30 / 01:00–04:00 | 加成，但避开韩股开收盘 ±1.5h | 基准 |
| 21:30–01:00 + 周末 | 加成核心 | 基准（`boost_multiplier: 1.0`） |

默认把 `boost_multiplier` 设为 **1.0**：加成窗口的 15% 初始保证金本身就是上限
（每边 3.0× ⇒ 占用 90% 权益），**再加杠杆只是加风险，加不进名义**。
想更激进就调 `base_per_side`，并接受强平距离变短。

### 4.3 止损阶梯：按「权益自峰值回撤」，不按「保证金占用」

这是全仓库最容易搞错、也最值得抄的一点：

| 量 | 决定什么 |
|---|---|
| 初始保证金 IMF（10% / 15%） | **能开多大**。占用 100% 只是不能再开新仓，不是危险 |
| 维持保证金 MMF（股票类 6.667%） | **什么时候被强平**：`权益 < 总名义 × MMF` |
| **安全指标 `R = 权益 ÷ 维持保证金`** | `R = 1` 才是强平线。**风险只看这个** |

```yaml
stops:
  ladder:
    - {trigger_pct: 12.0, action: de_lever, target_per_side: 2.0}
    - {trigger_pct: 20.0, action: de_lever, target_per_side: 1.5}
    - {trigger_pct: 30.0, action: flatten_and_halt}
  recovery: {within_pct: 1.0, hold_hours: 24}   # 回到峰值 1% 内并维持 24h，才逐级恢复
```

止损位置按「历史最深回撤」和「结构性尾部」定：股票永续有 ±5% 价格带，
四条腿反向走满时价差一天能走约 1,000 bps —— 这就是结构性尾部。
**先定你愿意亏多少，再换算成 spread 要走多少 bps**；不要先拍一个「权益 −5% 就降杠杆」。

### 4.4 ADL 复位：浮盈本身就是风险

Arcus 有 ADL（自动减仓）。排序规则不公开，但通行规则是**按「盈利 × 杠杆」挑对手方** ——
所以一条腿的浮盈越大，越容易被选中。做法是把浮盈兑现掉：

```
任一腿浮盈 ≥ 该腿保证金的 leg_pnl_pct（默认 10%）
  → 平掉整个篮子 → 按触发时的同样大小重开 → 冷却 1800s
```

| 项 | 值 |
|---|---|
| 触发口径 | **每腿保证金**（不是名义）：3.0× 下 10% 保证金 ≈ 3.3% 的价格移动 |
| 成交方式 | 平仓与开仓**都先挂 maker**，5 分钟不成交才撤单改 taker |
| 与冻结模式的关系 | 冻结挡的是「调仓」；复位是**风控动作**，照常执行 |
| 与熔断的关系 | `HALT` / −30% 熔断状态下**放弃**复位（那两种状态只允许减仓） |
| 状态落盘 | `state/spread_adl_reset.json`（阶段机）+ `state/spread_pending.json`（挂单） |

阶段机落盘是必须的：一次复位跨多轮（平仓可能等 5 分钟），
daemon 中途重启要能接着跑，否则会出现「平完忘记开」或「开出两倍」。

### 4.5 手工刹车

| 触发 | 效果 |
|---|---|
| `touch state/STOP` | 全局停机：不下任何新单（调度器与账户级工具都认） |
| 不加 `--apply` | 只报告、不下单（**影子期默认**） |

## 7. 估分：能拿多少分

### 7.1 模型

```
OI-time     = ∫ |净名义| dt        （按市场、取绝对值；多空两条腿都算）
平均 OI     = OI-time ÷ 窗口小时数
积分（周）  ≈ (OI-time 的 $M-week) × 效率
效率        ≈ 1,000–4,000 分 / $1M-week
              （加密币对 ≈ 900–1,100；RWA / 股票 ≈ 3,000–4,000）
加成        = 落在 20:00–04:00 ET + 周末 的那部分 OI-time
```

平台侧的硬上界：每周发放 **250,000 分**，平台 OI 总量约 **$64M**
⇒ 平台平均效率上限约 **3,903 分 / $M-week**，而成交量、存款、推荐等路径还要分走一部分。
所以**低端才是普通账户的诚实预期**；要跑到高端必须叠加 RWA + 隔夜加成 + 存款/推荐。

### 7.2 自己跑

```bash
# 读交易所成交账本，默认最近 7 天
.venv/bin/python tools/points_report.py --config config/mainnet.yaml --days 7
# 指定窗口
.venv/bin/python tools/points_report.py --config config/mainnet.yaml \
    --since 2026-10-08T11:11:00+08:00
# 离线：把 /v1/fills 的结果存成 JSON 之后
.venv/bin/python tools/points_report.py --fills-json state/fills.json --days 3
```

输出包含每个标的的成交笔数、换手、**OI $h**、**平均 OI**、持仓时长分位、
**加成占比**、容量占用与积分区间。

### 7.3 怎么读

| 你看到的 | 含义 | 该动什么 |
|---|---|---|
| 平均 OI ≈ 0 而换手很大 | 你在赚价差，不在拿分 | 把「持仓」的时间尺度拉长 |
| 持仓中位数是分钟级 | 行为画像接近被折扣的那一类 | 同上；这是**风控也是提分** |
| 加成占比低（约 30%） | OI 大部分落在常规时段 | 偏置到 20:00–04:00 ET + 周末，或干脆 24/7 持有 |
| 积分只有个位数/周 | 在这个本金规模下是正常的 | **只有资本能改变量级**，参数只能改善斜率 |

数量级校验表（gross OI 满持一周）：

| gross OI | @900 分/$M-week | @2,000 | @4,000 |
|---|---|---|---|
| $5k | 5 | 10 | 20 |
| $20k | 18 | 40 | 80 |
| $50k | 45 | 100 | 200 |
| $150k | 135 | 300 | 600 |

## 8. 风险与边界（必读）

### 8.1 会真的亏钱的机制

| 风险 | 机制 | 本仓库的处理 |
|---|---|---|
| **强平** | 跨保证金下 `权益 < 总名义 × 6.667%` | 用 `R = 权益 / 维持保证金` 监控；止损阶梯按 `R` 定 |
| **ADL** | 按「盈利 × 杠杆」挑对手方减仓 | ADL 复位：浮盈到该腿保证金 10% 就平掉重开 |
| **±5% 价格带** | 股票永续有涨跌停带，四腿反向走满 ≈ 价差 1,000 bps | 当作**结构性尾部**，止损档位排在它之前 |
| **资金费** | RWA 多头长期付费（实测约 0.000506%/h ≈ 4.4%/年），每小时结算 | 优先做收资金费的一边；持仓时间是真实成本 |
| **手续费** | beta 期 maker 0 / taker 225 ppm；优惠结束后 maker 150 ppm | 有效止盈 = `max(配置值, maker 费率×2)`，从 `/v1/feeTiers` 实时读 |
| **ETF 权重变化** | 主动管理 + 季度再平衡 | 定期重算权重与可交易比例，否则敞口会悄悄改变 |
| **溢价/折价与分红** | perp 跟踪场外价格；除息日会一次性错位 | 事件前降仓，或接受一次性噪声 |
| **流动性与滑点** | 小盘腿盘口很薄 | `min_order_notional`、单笔上限、maker 优先 |

### 8.2 规则风险（比市场风险更不可控）

- **积分规则是黑盒**，可以追溯调整；官方明确点名 wash trading / self-matching /
  刻意聚类 / 快速存取循环会减分。本仓库把行为做成「长期持仓」，
  但**这不构成合规保证**，请自行阅读并遵守交易所条款。
- **排名分配**意味着你拿多少分取决于别人做多少，你无法「锁定」一个分数。
- **单周快照不能当公式**：所有效率锚点都是量级，方向可信、幅度不可信。
- 本仓库**不是投资建议**，作者不对任何使用后果负责。先小资金，先在测试网。

### 8.3 密钥与个人数据

- 仓库里**没有任何密钥、助记词、地址或账户数据**；配置模板全部是占位符。
- 告警 webhook、API 私钥、`state/`、`logs/` 全部在 `.gitignore` 里。
- 推送到任何远程之前，确认没有把 `config/*.yaml`（`example.yaml`、`spread-v2.yaml` 除外）
  和 `state/` 加进去。

## 9. 研究目录：spread-lab

`spread-lab/` 是「策略为什么是这个形状」的证据来源。脚本只依赖标准库与公开行情接口：

| 脚本 | 回答的问题 |
|---|---|
| `fetch_candles.py` | 拉公开 K 线（1h / 1m，按 `to` 倒序分页） |
| `analyze.py` | 相关性、β、ADF / Hurst / 半衰期、z 统计 |
| `extras.py` | 样本内外稳定性、多腿对冲、容量、tick |
| `grid2.py` | 价差网格模拟（多档距 × 多锚） |
| `sessions.py` | 交易时段 vs 非交易时段：波动、回撤、杠杆空间 |
| `leverage_windows.py` | 加成窗口排班与最小定倍数（回撤预算 / 等波动 / 保证金 三约束） |
| `leverage_envelope.py` | 杠杆包络：某个倍数下还能跌多少 |
| `plan_L2.py` | 某套排班的保证金可行性、回撤、积分、止损 |
| `risk_mm.py` | **用维持保证金而不是初始保证金**衡量风险（`R` 的出处） |
| `points.py` | 持有 vs 网格的 OI-time 与积分比较 |
| `strategy_v2.py` | 生成策略 v2 的参数快照与可视化页 |

```bash
cd spread-lab

python3 analyze.py && python3 sessions.py && python3 leverage_windows.py

LAB_EQUITY=20000 python3 strategy_v2.py           # 换成本地权益重算
```

## 10. 为什么仓库里没有 V1

| | V1（**不在**本仓库） | V2（本仓库） |
|---|---|---|
| 形状 | 单腿 maker 网格 | 多腿美元中性价差 |
| 目标 | 完成轮次 / 每轮价差 | 持续 OI-time |
| 行为画像 | 分钟级持仓、零手续费、高频循环 | 小时级以上的持仓 |
| 对积分 | 接近 0，且落在被折扣的那一类 | 主项 |
| 退役原因 | 实测「阶梯上限只用掉 1.2%」—— 资本没变成 OI | — |

V1 的代码（网格引擎、单腿调度、网格回测）**不在本仓库**。它的历史结论只保留一句：
**它证明了「赚价差」和「攒积分」优化的是两个不同的变量。**
V1 的策略语义来自 [`perp-dex-tools`](https://github.com/your-quantguy/perp-dex-tools)
的 `trading_bot.py`（非商业许可）；本仓库的执行层是独立实现，与它无关。
