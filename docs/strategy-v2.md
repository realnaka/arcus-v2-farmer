# 策略 V2 设计说明

参数在 [`arcus-farmer/config/spread-v2.yaml`](../arcus-farmer/config/spread-v2.yaml)，
调度器在 [`arcus-farmer/tools/spread_schedule.py`](../arcus-farmer/tools/spread_schedule.py)。
本文件解释**每个参数为什么是这个值**，以及改动它会影响哪个裁判。

---

## 1. 形状

```
多：MU-USD   按 ETF 内权重 27.36% / 可交易合计 54.14% = 0.5054
    SKHY-USD                    22.13% / 54.14%      = 0.4088
    SNDK-USD                     4.65% / 54.14%      = 0.0859
空：DRAM-USD  每边名义 100%
```

每边名义 = `base_per_side × 权益`。默认 `base_per_side = 3.0` ⇒ 总名义 = **6.0× 权益**。
美元中性：多腿合计 = 空腿 = 每边名义。

净敞口 ≈ 做空 ETF 里**在 Arcus 上没有对应永续的那 45.86%**（三星 25.3%、CXMT 5.3%、
希捷 4.2%、西部数据 3.3%、铠侠 3.2%、南亚 2.5%、华邦 1.1%）。
其中三星占空头腿的约 55% —— **这条腿无法直接对冲**，是结构里最大的单一残差。

## 2. 杠杆的数学：先分清三个量

| 量 | 取值 | 决定什么 |
|---|---|---|
| 初始保证金 IMF | 常规 10% / 加成窗口 15% | **能开多大**。占用 100% 只是不能再开新仓 |
| 维持保证金 MMF | 6.667%（股票类） | **什么时候被强平** |
| **安全指标 R** | `R = 权益 ÷ (总名义 × MMF)` | `R = 1` 才是强平线 |

总名义 = `2L × 权益`（L = 每边名义/权益），于是：

```
R                = 1 / (2L × MMF) = 7.5 / L
强平所需价差位移 = (1 − 2L × MMF) / L × 10⁴  bps
初始保证金占用    = 2L × IMF        （常规 10% / 加成 15%）
```

| 每边 L | 总名义 | 进场 R | 强平要 spread 走 | 常规占用 | 加成占用 |
|---|---|---|---|---|---|
| 1.0× | 2.0× | 7.50× | 5,000 bps | 20% | 30% |
| 1.5× | 3.0× | 5.00× | 4,444 bps | 30% | 45% |
| 2.0× | 4.0× | 3.75× | 3,667 bps | 40% | 60% |
| 2.3× | 4.6× | 3.26× | 3,014 bps | 46% | 69% |
| **3.0×（默认）** | 6.0× | **2.50×** | **2,000 bps** | 60% | **90%** |
| 3.33× | 6.67× | 2.25× | 1,750 bps | 67% | 100%（IM 打满） |

读法：

- **加成窗口的 15% 初始保证金本身就是上限**。每边 3.0× 时占用已 90%，
  所以 `boost_multiplier` 默认 1.0 —— 在加成窗口再加杠杆加不进去，只能加风险。
- **结构性尾部决定上限**：股票永续有 ±5% 价格带，四腿反向走满 = 价差 ~1,000 bps；
  扩张带（换标的/带子放宽）~2,000 bps。选 3.0× 时强平距离正好等于扩张带 ——
  也就是说**默认参数已经贴到「最坏结构情形」的边界**，不再留余量。想要余量就降 L。

## 3. 排班（ET 时钟）

Arcus 的「常规时段」是 **04:00–20:00 ET**（`/v1/markets` 的 `regularTradingHours`，
含美股盘前盘后），其余是加成窗口。

| ET 时段 | 归类 | 处理 | 理由 |
|---|---|---|---|
| 04:00–20:00 | REG | 基准仓位 | 无加成 |
| 20:00–21:30 | BOOST_EDGE | 基准仓位 | 韩股开盘 ±1.5h，波动率高 |
| 21:30–01:00 | **BOOST_CORE** | 基准仓位（可乘 `boost_multiplier`） | 加成 + 避开韩股开收盘 |
| 01:00–04:00 | BOOST_EDGE | 基准仓位 | 韩股收盘 ±1.5h |
| 周末 | BOOST_CORE | 基准仓位 | 加成最多，但要连挂 48h |

`korea_avoid` / `us_avoid` 是给「什么时候**不**加杠杆」用的：
韩股开收盘 ±1.5h 的波动率大约是被排除窗口的两倍，用相同的保证金去换更颠簸的路径不划算。

## 4. 止损阶梯

```yaml
stops:
  ladder:
    - {trigger_pct: 12.0, action: de_lever, target_per_side: 2.0}
    - {trigger_pct: 20.0, action: de_lever, target_per_side: 1.5}
    - {trigger_pct: 30.0, action: flatten_and_halt}
  recovery: {within_pct: 1.0, hold_hours: 24}
  peak_reset_pct: 50.0
```

**触发量是「自峰值权益的回撤百分比」**，不是市场价跌幅，也不是保证金占用。

为什么这么定：

| 原做法（错） | 现在（对） |
|---|---|
| 按「初始保证金占用」设线 | 占用是**能力**指标（能不能开新仓），不是风险指标 |
| 线贴着强平线 | 线按「历史能跌到哪」+「你愿意亏多少」定 |

12% / 20% / 30% 的实测对照（L=3.0×）：

```yaml
-12%            每边 3.0 → 2.0     降杠杆后 R 仍 ≥ 2.9
-20% ≈ 1,000bps  每边 2.0 → 1.5     ≈ ±5% 价格带打满的结构性尾部，R ≥ 2.6
-30% ≈ 1,500bps  全平 + HALT        落在价格带与扩张带之间，R ≥ 2.3
```

恢复是**棘轮**：回到峰值 1% 以内并维持 24 小时，才升一档；权益创新高超过 50% 才清空 `HALT`。

## 5. 执行

| 参数 | 值 | 含义 |
|---|---|---|
| `maker_first` | true | 调仓默认挂 post-only |
| `fill_timeout_s` | 300 | 5 分钟不成交 → 撤单改 taker |
| `through_bps` | 40 | 改 taker 时的穿越幅度（防止坏盘口吃飞） |
| `reduce_is_always_taker` | true | **减仓/止损直接吃单**，不等 maker |
| `grid_rung_policy` | requote | 普通挂单超时撤单重挂，不吃单 |
| `min_order_notional` | 5 | 小于这个差额不下单（死区，防抖） |
| `ladder_residual_notional` | 50 | 冻结模式下补完减仓的最低差额 |
| `max_leg_notional_usd` | 250 | 单腿日内容量约束（小盘腿是瓶颈） |
| `max_rounds_per_day` | 16 | 轮次上限（anti-churn） |

**方向性区别**：加风险的动作等 maker（省手续费）；**降风险的动作不吃等待**。
ADL 复位是唯一例外 —— 它按操作要求「平仓也先挂 maker」（见下）。

## 6. ADL 复位

### 6.1 为什么

Arcus 有 ADL，且是 production 代码路径：订单状态枚举里有 `ADL`，
成交里带 `liquidation.method = ADL` 与 `liquidatedUser`，被减仓的腿不收 fee。
**排序规则不公开**，但通行规则是「按盈利 × 杠杆挑对手方」——
所以**浮盈本身就是风险**。

### 6.2 做什么

```
任一腿未实现盈亏 ≥ 该腿保证金的 leg_pnl_pct（默认 10%）
  → 卖出/买回整个篮子到 0
  → 按触发当时的同样大小重开（对冲腿先走，多腿按实际成交的空头重算，保持美元中性）
  → 冷却 cooldown_s（默认 1800s）
```

口径：`leg_pnl_pct` 是**每腿保证金**，不是名义。L=3.0× 时 10% 保证金 ≈ **3.3% 的价格移动**，
落在 ±5% 价格带之内；按名义口径则永远不可能触发。

### 6.3 状态机必须落盘

一次复位跨多轮（平仓可能等 5 分钟），daemon 中途重启必须能接着跑：

| 文件 | 内容 |
|---|---|
| `state/spread_adl_reset.json` | 阶段机（idle / closing / reopening / cooling） |
| `state/spread_pending.json` | 未成交挂单 |
| `state/adl_reset_log.jsonl` | 事件流水（影子期就是靠它事后审计） |

否则会出现「平完忘记开」或「开出两倍」。

### 6.4 与其他状态的关系

| 状态 | 复位是否执行 |
|---|---|
| `hold_rebalance: true`（冻结调仓） | **执行**（复位是风控动作，不是调仓） |
| `HALT` / −30% 熔断 | **放弃**（那两种状态只允许减仓） |
| `state/STOP` | 不下任何新单 |

### 6.5 验收（照「先定裁判」的约定）

| 项 | 内容 |
|---|---|
| 影子期 | dry 模式跑 7 天，把 `adl_reset_log.jsonl` 与实际浮盈曲线逐条对齐 |
| 裁判 | ① 未被 ADL/强平次数（目标 0）② 复位摩擦成本 ③ 同一腿 1 小时内是否重复触发 |
| 达标线 | 7 天无 ADL、单次复位摩擦可控、重复触发 0 次 → 保持开启；否则调 `leg_pnl_pct` 或退回只报告 |
| 回滚 | `adl_reset.enabled: false` + 重启 |

## 7. 冻结模式（hold）

```yaml
mode:
  hold_rebalance: true
```

冻结时**仓位完全不跟实时权益/价格漂移**，也不做窗口切仓。仍然活着的只有：

| 还活着 | 已停掉 |
|---|---|
| 止损阶梯降杠杆（**只降不升**，每档只触发一次） | 窗口切换调仓、权益漂移调仓、任何加仓 |
| −30% 熔断全平 | 挂单超时改 taker 的循环 |

档位触发时把**目标尺寸冻进** `state/spread_ladder.json`，
之后每 60 秒只用冻结目标补完没成交的减仓（差额 ≥ `ladder_residual_notional`），
所以价格漂移不会再产生订单。

**这个模式是被实测逼出来的**：第一版 daemon 每 15 秒盯市一次，2.5 小时下了 124 单 /
66 次调仓，稳定期约 40 笔/小时，单笔 $5–$25 —— 全部来自「权益抖了几美元」和
「没有死区的差额下单」。对积分是负分，对手续费是纯支出。

## 8. 告警阈值

全部按**权益比例**（加本金后自动缩放），由 `tools/margin_watch.py` 评估：

| 级别 | 触发 | 性质 |
|---|---|---|
| L1 | 回撤 ≥ 12%；维持保证金缓冲 < 60%（R < 2.5）；可用抵押 < 24% 权益 | 提示 |
| L2 | 回撤 ≥ 20%；缓冲 < 50%（R < 2.0）；可用 < 15% | 警告 |
| L3 | 回撤 ≥ 30%；缓冲 < 40%（R < 1.67）；可用 < 6% | 紧急 |

要点：

- **初始保证金占用只作容量提醒**（加成窗口直接关闭告警）——它是能力指标。
  真正的风险告警是**维持保证金缓冲**。
- 阈值必须落在「目标仓位本身的进场 R」之下，否则目标仓位天天触发 L1。
  L=3.0× 的进场 R = 2.50 ⇒ 缓冲 60%，所以 L1 定在 60%。
- 同级冷却 6 小时，升级立即发；推送走 webhook（URL 从环境变量读，不进仓库）。

### 首次实战暴露并修复的两个缺陷

1. **旧 mid 会拒单**：`mids` 原本每 10 分钟才刷一次，等完 5 分钟 maker 再报价时用的是旧价，
   ALO 直接穿价被拒。改为 daemon 每 60 秒刷一次 mid。
2. **被拒的 ALO 会死循环**：对冲腿 ALO 被拒后没有 pending 记录，每轮重挂、永远走不到
   「超时改 taker」。改为对冲腿两次被拒直接吃，普通腿记一条无 `order_id` 的 pending
   让 5 分钟计时跑起来。

## 10. 已知缺口

| 缺口 | 影响 |
|---|---|
| 无真实对冲腿（三星等） | 净敞口残差只能靠 SKHY 间接部分对冲 |
| 单边报价，非双边 MM | 拿不到官方「Make markets（tight/deep/consistent）」口径 |
| 无 funding 方向自动选择 | 长期 OI 可能固定付费；应自动选收 funding 的一边 |
| 无时段偏置的自动调仓 | 冻结模式下加成占比靠「一直持有」自然获得 |
| 事件级处理（分红/拆股） | 公司行动通过 funding 传导，尚未做事件级处理 |
| 积分异常告警 | 「连续两周点数 ≈ 0」的停机线还没接进告警 |
